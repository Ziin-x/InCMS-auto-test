# 标注规范（Label Guide）

标注对象：`dataset.py` 里 100 条失败样本。给每条样本的 `label` 字段填五类之一。

## 一、五类定义

| 分类 | 定义 | 典型特征 |
|---|---|---|
| `application_bug` | 产品/业务代码缺陷 | 断言失败，且期望值来自需求文档/业务规则；页面行为与规格不符 |
| `test_bug` | 测试脚本自身缺陷 | 定位器失效、期望值写死/写错、测试数据生成错误、断言逻辑写错 |
| `environment_issue` | 环境问题 | 连接失败、接口 5xx、证书/DNS 错误、限流、登录态失效、环境配置错误 |
| `flaky_test` | 偶发/不稳定 | 有明确"重跑通过""偶发""无规律"证据，且错误非确定性 |
| `unknown` | 证据不足 | 只有表面错误，无任何可判断的上下文 |

## 二、关键判定规则（边界案例按此执行）

1. **接口 5xx**（500/502/503/504）→ `environment_issue`
2. **接口 404** → `application_bug`（接口契约被破坏）
3. **401/403/429** → `environment_issue`（除非样本里有产品权限逻辑缺陷的明确证据）
4. **连接类错误**（REFUSED / TIMED_OUT / DNS / SSL / 证书 / NETWORK_CHANGED）→ `environment_issue`
5. **定位器找不到元素 + 改版/文案变更证据** → `test_bug`
6. **"重跑通过 / 偶发 / 无规律"** → `flaky_test`
7. **只有表面错误、无任何上下文** → `unknown`
8. **标注根因，不标表面现象**：表面是 TimeoutError，但根因可能是环境挂了（→environment）或选择器失效（→test_bug）。看备注和日志下判断

## 三、标注流程（重要，按顺序做）

1. **独立标注**：自己把 100 条的 `label` 填完。**不要先看 gold_labels.py**，否则双人标注就失去意义
2. **对照**：标完后对照 `gold_labels.py`（我的标注），找出不一致的条目
3. **讨论**：每条不一致的样本都是"边界案例"，想一想为什么我们会标不同——这些正是评测集里最有价值的样本
4. **定稿**：最终以你的标注为准（我只是一名标注者，你的领域知识比我强）

## 四、争议处理

- 两个标注者都能自圆其说 → 该样本标记为"困难样本"，记进 `EVAL.md`
- **争议率 = 不一致条数 / 总条数**，这本身是评测质量指标：
  - 争议率 < 10%：规范清晰，评测可信
  - 争议率 > 20%：规范不够清晰，需要修订规范后重标
